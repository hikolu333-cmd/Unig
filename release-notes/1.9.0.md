# UniGeek 1.9.0
*2026-11-15*

First release where the **diy_joystick** board runs on verified real hardware: a bare ESP32-S3 devkit + 2.8" ILI9341-family SPI TFT + KY-023 analog stick. Plus a new way to drive any board from a PC.

## New Features

> **diy_joystick bring-up on real hardware**
> The DIY board (ESP32-S3 devkit + 2.8" ILI9341-clone TFT + KY-023) is now verified end-to-end: boot → splash → menu. Pin map matches the reference wiring (CS=21, DC=47, MOSI=38, SCLK=39, BL=40, RST tied to EN, stick VRx=1/VRy=2/SW=42, 16MB flash).

> **PC Remote over USB CDC**
> While the physical stick is unwired, the device can be driven from a PC keyboard: WASD/arrows navigate, Enter selects, Backspace goes back, H long-presses. Implemented as a board hook on the shared `INavigation::inject()` path — no screen logic touched, works alongside any input hardware.

## Fixes

> **ESP32-S3 + TFT_eSPI bootloop (StoreProhibited)**
> On Arduino core 2.x the default `SPI_PORT=FSPI(0)` resolves IDF register macros to `REG_SPI_BASE(0)==0`, so the first `SET_BUS_WRITE_MODE` writes to address 0x10 and panics. The board now defines `USE_FSPI_PORT`, mapping TFT_eSPI onto the real SPI2 registers. diy_joystick was the first S3 board using TFT_eSPI — every other S3 board uses M5GFX, which is why CI never caught it.

> **PSRAM assumption removed**
> The board manifest advertised `BOARD_HAS_PSRAM` for a module that has none — heap_caps allocations returned NULL and crashed at the first dereference. Flag dropped.

> **Photo-negative colors on ILI9341 clones**
> The panel renders inverted without an explicit `INVON`. `TFT_INVERSION_ON` is now set for this board.

> **Display blinking with floating analog inputs**
> Unwired VRx/VRy pick up noise that reads as random directions and wakes the display from power-save, producing a periodic blink. Navigation input is frozen behind `JOYSTICK_NOT_WIRED` (remove the define once the stick is soldered) and power-save defaults to off on this board.

> **Linker conflict with libnet80211**
> `WifiAttackUtil`'s deliberate `ieee80211_raw_frame_sanity_check` override collided with `libnet80211.a`. The board env now passes `-Wl,--allow-multiple-definition` (first definition in link order wins, so the override still works).

> **Boot diagnostics**
> `setup()` now prints `[BOOT]` stage markers to Serial, making "where did it die" a one-glance question on every board.
